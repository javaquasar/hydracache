# Bounded local WSL preparation session

This private diagnostic runner encloses metadata, six serial healthy preparation
profiles and postflight in one WSL process. It is not a production controller or
an admission authority. The previous refused residual packet stays closed.

The schedule is GNU 1.94 samples 0–2, then MSRV 1.88 samples 0–2. A nonzero
profile stops its lane; metadata drift, containment failure or interruption stops
the entire session. Nothing retries. An existing packet directory refuses entry,
including an incomplete packet left by SIGKILL. A missing terminal receipt is
incomplete evidence, never permission to resume or declare successful cleanup.

Fresh default-feature images are built as the ordinary WSL user and pinned
before entry. The unchanged runtime tree inherits the preceding packet's 155
focused checks per compiler, affected checks and strict lint. Those checks are
not relabeled as newly executed. Root is used only inside the synthetic local
fixture session; no root rustup query or automatic toolchain installation occurs.

The exact original test, healthy case, synthetic nine-file bundle and fixed
300/60/10 admission windows remain. Each child retains the original 1200-second
timeout and five-second termination grace. Additional containment is 1210 seconds
per child, 7500 seconds per session, and an outer 7530-second timeout including
preparation verification. Logs are capped at 32 MiB per child. These are wrapper
bounds, not extensions to the Rust admission windows. Metadata subprocesses have
ten-second timeouts. No session keepalive, daemon, clock, service or idle-policy
change is used.

Read-only observations before/after each profile compare source, tracked
cleanliness, boot, parent PID/start ticks, configuration, original bundle,
qualification, driver, pins, preparation receipt and both images. Unexpected
matching fixture residue refuses continuation; the runner never removes it.
Snapshots do not establish atomic filesystem identity, stable wall time or
cessation of all writers. Those checks remain in the original harness. On
interruption the runner terminates only its fresh child process group and tries
postflight. External SIGKILL/host loss can prevent cleanup/postflight; such a
packet is incomplete. Inner child timeouts remain independently active.
