# HydraCache 0.67.1 - Dedicated performance reference bootstrap

Status: **shipped evidence milestone; W0-W7 complete**.

This was completed after the product workspace had advanced to `0.70.0`. It publishes dedicated
performance evidence and methodology, not a new source package, and therefore does not create a
misleading `v0.67.1` crates.io release from the later source tree.

## Reviewed activation

The `reference-v1` profile is bootstrapped from exactly five successful, chained, pre-candidate
`main` runs at commit `b3304e3a560fdddaf820d813a76773ca33565c50`. All five runs used one
privacy-safe v5 runner fingerprint, one admitted host contract, Rust `1.94.0`, Ubuntu 24.04 with
kernel `6.8.0-138-generic`, and the same exact scenario, workload, SLO, prebuild, and stable
methodology identities.

The admitted host was non-virtualized bare metal with an AMD Ryzen 7 PRO 8700GE, 64 GiB-class RAM,
local NVMe, SMT disabled, performance governor, turbo enabled, measurement CPUs `1-4`, and
housekeeping/IRQ CPUs `0,5-7`. Provider addresses and hardware identifiers are intentionally not
published.

The deterministic proposal retained all five eligible samples and selected the median for every
budget instead of choosing the fastest run. Independent review approved the exact profile, anchor,
rolling baseline, and budget bytes. The committed 10% immutable-anchor/rolling tolerance and 5%
frozen-candidate per-report spread ceiling remain unchanged. Candidate comparisons use the larger
of that relative tolerance and a conventional robust three-sigma envelope derived from the
authenticated rolling MAD; the allowances are not added. This prevents a single frozen
observation from being rejected merely because the selected median is narrower than the measured
five-sample noise distribution.

The W5C grid-model timing window was subsequently corrected from 100/1,000 warmup/measured
iterations to 1,000/10,000. The shorter window repeatedly produced an approximately 8.2% bimodal
spread for sub-100 ns unavailable-replica decisions, and four of its five reviewed bootstrap
reports exceeded the later 5% frozen-candidate ceiling. The correction keeps the 5% ship ceiling
and the measured primitive/SLO unchanged; exact one-way digest bridges admit only the reviewed
legacy W5C contract into the longer successor window. All unrelated scenario, workload, SLO, and
methodology changes still fail closed.

## Claim scope

The reviewed contract covers only the exact 0.67 scenarios and method on this admitted host:

- the embedded local cache and in-process Axum client surface;
- one selected node-local RESP endpoint, plus a pinned same-box Redis comparison;
- real three-, five-, and seven-daemon control-plane operations;
- explicitly labelled library/model grid primitives;
- surface-specific brownout and overload measurements.

These values are not portable sizing guidance, a universal Redis comparison, distributed RESP
capacity, aggregate cluster capacity, native-daemon client performance, or live-reshard
performance. Hardware, kernel, CPU topology, governor, turbo, storage identity, toolchain, or
scenario-contract drift requires requalification and a new reviewed baseline family; it never
causes automatic baseline migration.
