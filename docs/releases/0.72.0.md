# HydraCache 0.72.0 — Management Center 2.0 and operational visibility

Status: **shipped 2026-09-22** from exact qualified candidate
`24927c28c279c6c34ad90111ee6470b4065e0815`.

0.72 replaces the single-page observe-only console with a locally bundled TypeScript/component
application and a versioned, read-only `/management/v1` API. Operators now have routed dashboard,
member and partition, HC/1-HC/2-RESP client, namespace/cache, health, persistence, operation,
metrics and audit views. Cluster aggregation is authenticated and bounded. Every observation
states whether it is live, modeled or unavailable; fresh or stale; complete or partial.

The browser remains read-only. This release does not add arbitrary proxying, browser-to-member
fan-out, state-changing controls, unbounded history, sensitive identifiers, a new storage engine
or a numerical performance claim. Optional Prometheus history uses only fixed reviewed queries.
Missing or mixed-epoch evidence is shown as unknown/partial and cannot become a green health state.

hourly fault schedule and FD/RSS/latency ceilings were not weakened.

every 50 ms admission decision. The candidate bounds detailed diagnostics to a 1,024-entry FIFO

verify newest-entry retention; Linux one- and three-daemon isolation profiles changed the idle
behavior from linear growth to a stable RSS plateau; the complete six-hour and 24-hour contours
then passed.
