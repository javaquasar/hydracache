# HydraCache 0.74.1

**Status** — release candidate. Rust 1.88 remains the minimum.

The 0.74.0 workspace requires reviewed dependency patches. Cargo strips
workspace patches when it normalizes a package for crates.io. The 0.74.1
plan uses exact registry versions of the reviewed forks to carry those
changes into independent consumers.

Each digest covers the sorted map of relative `src/` and `proto/` paths to
their content SHA-256 values, encoded as compact JSON. The starting Raft,
sled and SQLite driver sources came from the vendored copies in
`v0.74.0`. The SQLx facade and its two compiler companion crates came from
upstream `sqlx 0.8.6`. The compatibility run records the current sources
and executables separately.

The proposed SQLite adapter exposes the driver through
`hydracache_sqlx::sqlx` and `hydra-sqlx`. An application that also selects
SQLite from upstream SQLx 0.8.6 or through SeaORM's upstream SQLite driver
can select an incompatible native SQLite binding. PostgreSQL continues
to use the shared upstream `sqlx-postgres 0.8.6` type identities.

The local candidate connects the SQLx facade and the compile-time macro
backend to the same reviewed SQLite driver through
`hydra-sqlx-macros` and `hydra-sqlx-macros-core`. It uses
`libsqlite3-sys 0.40.0` across SQLx and Diesel. The standalone SQLx audit
includes the conditional SQLCipher test dependency, `sqlcipher-src 420.0.0`.
SQLx keeps its upstream SQLite macro and migration tests and uses Tokio
and `pastey` for test support.

Raft updates its benchmark and fixture runners and pins the logging
dependency. sled updates its QuickCheck, random-number and logging test
dependencies plus the compression and backtrace dependencies exercised by
its testing feature. The separate Raft, sled and SQLx test graphs and the
Linux candidate lockfile passed RustSec on Rust 1.88 with the original
policy.

The local x86-64 Linux server built with Rust 1.88 has SHA-256
`6d91f1f566b19a81a4f12e8a09a0831c8abe9da4f108869e9ba18b326c15dc4f`.
It passed separate three-member rolling upgrades from the retained
`v0.74.0` and `v0.73.0` server executables and rollback to each baseline.
Each run preserved the same three volumes and verified 10 checkpoints
across 12 process generations.

All seven fork archives are on crates.io with their reviewed SHA-256
digests. A clean Rust 1.88 project downloaded those forks from crates.io,
used the 23 staged HydraCache archives, passed 14 consumer tests and
installed the server with `--locked`. RustSec found no advisories or
warnings in the consumer and packaged server lockfiles. GitHub Actions
repeats the checks against the public HydraCache release.

The separate auditable ELF has SHA-256
`e4109d7b1cc7fafcffb2f202118372e01ca57d995dd0ba1bb086ff8a78ceb5a9`.
Its embedded registry dependency inventory passed `cargo audit bin`.
The corresponding CycloneDX SBOM includes the versions of all five linked
`hydra-*` dependencies. This digest identifies the auditable binary for any
future AX42 qualification.
