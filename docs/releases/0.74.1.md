# HydraCache 0.74.1

**Status** — planned. Rust 1.88 remains the minimum.

The 0.74.0 workspace requires reviewed dependency patches. Cargo strips
workspace patches when it normalizes a package for crates.io. The 0.74.1
plan uses exact registry versions of the reviewed forks to carry those
changes into independent consumers.

Each digest covers the sorted map of relative `src/` and `proto/` paths to
their content SHA-256 values, encoded as compact JSON. The Raft, sled and
SQLite driver sources match the vendored copies in `v0.74.0`. The SQLx
facade matches the upstream `sqlx 0.8.6` source. Package metadata and
dependency declarations are reviewed separately.

The proposed SQLite adapter exposes the driver through
`hydracache_sqlx::sqlx` and `hydra-sqlx`. An application that also selects
SQLite from upstream SQLx 0.8.6 or through SeaORM's upstream SQLite driver
can select an incompatible native SQLite binding. PostgreSQL continues
to use the shared upstream `sqlx-postgres 0.8.6` type identities.

The initial facade passed the HydraCache runtime graph on Rust 1.88.
Generating its standalone lockfile also resolved SQLite through
`sqlx-macros-core 0.8.6`. That path requires `libsqlite3-sys 0.30.1` and
conflicts with the reviewed `0.39.1` driver. A local packaging candidate
resolves this conflict by dropping four forwards from the facade's
`chrono`, `json`, `time` and `uuid` features into the optional proc
macro. The runtime type features still reach the database drivers.
Compile-time SQL macros for those types need separate coverage before
accepting this facade revision.

The standalone facade audit still reports the upstream test dependencies
`async-std`, `pin-utils` and `paste`, as well as `sqlcipher-src` through
the conditional SQLCipher test configuration. A newer SQLite binding,
`libsqlite3-sys 0.40.0`, declares Rust 1.88 and resolves
`sqlcipher-src 420.0.0`. It needs separate SQLite and Diesel compatibility
checks before any version switch.

The exact fork versions, clean-consumer checks and artifact-level
compatibility must pass before switching the release lockfile to the
registry.

See the [Raft compatibility register](../COMPAT.md#raft-hash-tables-in-the-074-maintenance-line)
for the rolling upgrade evidence and its scope.
