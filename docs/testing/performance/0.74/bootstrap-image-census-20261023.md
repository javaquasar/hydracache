# Closed bootstrap image inventory under the original owner

The bootstrap join now retains a 26-descriptor, 14-role closed inventory. It
extends the prior 23/11 prefix with the original host image, original held
launcher and separately selected bootstrap image. This closes a prerequisite
before a child protocol can address those images; it does not enable that
protocol, a bootstrap executable, FD transfer, remapping or execveat.

## Why the earlier image check was insufficient

Baseline e40d4732 verified the signed bootstrap image and consumed the original
material owner, but its complete role census did not include all three images.
Checking an image hash separately did not establish that its descriptor was
disjoint from every existing role or that its descriptor state remained bound to
the same attempt. The [component plan](bootstrap-image-census-plan-20261023.md)
therefore puts their value-only census inside the already existing bootstrap
observation before adding a child execution boundary.

The private kernel contribution takes exactly 20 existing material stamps,
checks their CLOEXEC/non-O_PATH state and produces an opaque value. It has no FD
getter. The existing complete prefix supplies its three extra worker/guardian
descriptors and exact eleven-role mapping. The role provider borrows its actual
privately retained host/launcher files and the wrapper's bootstrap image; no
caller callback or alternate File is substituted for the original roles.

The extension requires 26 distinct nonnegative descriptor numbers, preserves
all eleven old mappings and appends host/launcher/bootstrap semantic roles
11/12/13. These indices are not an inherited-FD layout. The new images must be
readonly, CLOEXEC, regular, exactly four-sealed, nonempty and inside the old
binary bound, with expected device/inode/size. It rejects mutual inode aliases
and aliases of the prior worker. Repeated metadata/flags/offset stamps must agree;
the provider also compares both original role metadata stamps before and after.
The value cannot open, duplicate, borrow-export or transport a descriptor.

## Existing validation and refusal remain in force

The new census is part of Observation equality inside the same consumed
BootstrapOwnedUnit. It runs after the existing sealed-image/content check and
before the existing closing frames; no old frame is removed, merged or cached.
The three old full frames, signature/source checks and complete Context compare
remain unchanged. An offset change, same-bytes inode replacement or other new
census drift therefore follows the old shared-refusal/original-retirement path.

The old 23-descriptor prefix is authenticated by those original full frames,
not by the new value constructor alone. The extension does not independently
refresh old PID/guardian authority. Its tests deliberately model the old prefix;
they do not substitute that model for a real original-owner gate.

Three additive module hooks are the only changes to the old provider/census/
material-kernel bodies. A current-source guard reconstructs each entire old file
and the preceding bootstrap owner body, including its validation and retirement.
Hook duplication/mutation and unrelated body drift refuse. No new clock query,
hash round, environment change, file copy, FD duplication or callback is added to
the runtime path; all 300/60/10 origins and deadlines remain as before.

This is a runtime-only bounded array extension. No policy, receipt, wire,
durable schema, public API, default activation or installed configuration changes.
COMPAT, lockfile, gate registry and frozen qualification bytes remain unchanged.
The new bound stores 26 descriptor values, fourteen semantic slots and three
metadata stamps, not image contents or a growing collection. Old binaries do
not need to read any new serialized artifact. Removing this source candidate
does not permit retrying its consumed attempt; old refusal/retirement still apply.

## Next child entry boundary

Materialize the owned sealed child-entry binding from this closed owner, then
implement the independently enrolled bootstrap executable with fixed argument,
environment, credential and FD validation. Authenticate the original manager /
guardian context before the one-shot execveat of the same sealed launcher, with
no pathname fallback. Still require the real original join in unchanged windows,
all-writer cessation and SIGKILL/lost-ACK boundaries before completion/later cells,
reconnect or server admission. The inventory is a prerequisite, not a claim that
those execution gates are now implemented or passed.

The new metadata queries have bounded but unmeasured cost. Their effect on full
original preparation must be checked within the unchanged windows; unit elapsed
time does not establish that the original live path meets its admission deadline.
