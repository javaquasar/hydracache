# Transport capture attribution and the first reviewed package replay

One local Windows/debug cohort attributes bounded historical Git capture. It
does not establish an optimization: the installed transport is unchanged. The
default Windows package effect review is closed for its pinned inputs, but its
first complete-command replay reaches the original 780-second limit and remains
red. Neither result opens original execution or release admission.

## What changed

Code commit `3e9bcc06ebce3439495200162cb0c1900b8eda53` adds a diagnostic transport
mirror, held-child CPU observations, syntax/module inventory and a source-bound
manual effect-review receipt. The added controls live in `census_cost_074` and
`tools/historical-blob-batch-074`; no cache runtime source changes in this commit.

Erasing only observer calls and the diagnostic callback parameter must recover
the exact installed capture function. Private cleanup/bytes/deadline helpers and
constants are checked separately. `transport.rs`, the connected caller, independent
pins, conditional reads, panic API and all existing guards remain unchanged.
Capture keeps its 30-second deadline, five-second cleanup and original input,
stdout/stderr budgets and five-millisecond polling request. No ReservedLive
observation, predicate, order, frequency or 300/60/10 origin/window changes.

The fixed six ABBA/BAAB blocks contain twelve unobserved installed captures and
twelve mirror profiles. All 24 first samples are retained, without warmup,
discarded outliers or another measured child. Every invocation must return the
independently pinned 34850-byte BASE body with empty stderr. Record labels
`legacy`/`current` mean unobserved installed transport/profile mirror here, not
the earlier legacy/connected census comparison and not a product candidate.

Phase rows are medians of per-invocation totals, not additive partitions of the
median full call. Sleep overlaps useful Git work and host scheduling: 42.616 ms
is not an estimate of removable waiting. Child CPU comes from the same retained
Windows process handle at spawn/reap, with matching PID/creation identity and a
terminal exit time. Its final lifetime CPU is used, not a subtraction that loses
work completed before the first observation.

Parent CPU excludes Git and shows 15.625-ms quantization; its median is zero for
both paths. This cannot establish a CPU saving. Observer overhead is not
subtracted, and these within-process samples are not independent host replications.
The temporary-file/result-copy hypothesis is not supported as the main observed
owner. No polling, capture, caching or deadline candidate is installed or accepted.
This is MSVC/Rust 1.94 debug attribution, not native API or product throughput.
