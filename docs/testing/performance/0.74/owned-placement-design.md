# Signed placement constraints under the same live owner

The [approved local slice](owned-placement-plan-20261019.md) connects the v3
envelope reader to the same consumed original manager and armed root guardian
pair. The private result retains those exact owners and immutable envelope
bytes. It offers revalidation, not projection, delivery, completion or unlock.

## Original key consent and root

The new API accepts no verification key, root identity, replacement timer or
reconstructed original frame. Its concrete owner selects the existing retained
controller-policy key and compares the entire nested consent with the original
authenticated consent. Policy/epoch, current original peer, boot, freshness,
outputs and manager checks still run in the existing complete full round.
This is not authentication of a new incoming kernel peer exchange or enrollment
of a new production issuer.

The root adapter performs the old live observation, requires consumed enrollment
and both authenticated Armed replies, checks the packet kind and matches its
device/inode with the retained kernel root. It returns only the retained claims,
not a descriptor. A pending, uncertain, unarmed or refused pair cannot satisfy
the join. Independently deriving the original context digest and absolute bound
must reproduce that exact enrollment packet, not merely the same attempt ID.

## Complete live round and ownership

The algorithm reuses the unchanged root join with enrollment disabled. Pure
signature/consent/root comparisons run before and after its original full round.
Additional root observations bound the retained enrollment snapshot on both
sides. No original predicate, observation, refusal site, effect bracket, origin
or deadline is removed or replaced. Every revalidation repeats the signature
checks and full live round; the retained digest only forbids changing constraints.
It is not a cache of a successful authority check.

Success consumes the entire old OwnedRootGuardians object. Failure poisons both
owners and retains that complete consumed object behind the error. Neither path
returns a fresh retry owner or an output alias. Normal destruction uses the old
consuming holder's retirement and alias/custody destruction order. Independently
armed guardians still retain the original fence and timer. There is no explicit
unlock or new claim that these read-only checks prove all-writer cessation.

## Actual placement and artifacts remain separate

The accepted kernel root is the exact one retained by the original guardian
pair. This join does not prove that its parent/name is the expected systemd
slice; isolated local fixture roots deliberately have temporary names. It also
does not admit the v2 declared launcher/watchdog/collector digests as installed
executable objects. The envelope's original six false admission fields and
unchanged v1/v2/v3 bytes are not promoted to a new execution permission.

A subsequent projection must bind actual fixed slice ancestry and exclusive
population, approved artifact objects, streams, process/cgroup, barrier and
the same manager channel. The old direct-worker message remains unsent and
cannot be used as the held-launcher message. Authenticated delivery, writer
confinement, durable lifecycle, reconnect and server enrollment remain later
gates; no server or supervisor operation is part of this package.
