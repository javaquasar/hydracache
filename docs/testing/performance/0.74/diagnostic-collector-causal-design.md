# Post Reserved challenge and authenticated response

A newly dequeued heartbeat is not necessarily a response to the retained
reservation. The causal preflight binds one authenticated response to an
unpredictable challenge generated by the original owner after acknowledging
Reserved. It changes no durable state and grants no Starting capability.

## Challenge commitment and ownership

issue_progress_challenge consumes the acknowledged original reservation. Its
unchanged revalidation precedes one ring SystemRandom fill of 32 bytes. A sample
from the original kernel receiver follows entropy generation. Canonical LF JSON
contains the random hex, full original controller-attempt and Reserved byte
hashes, SHA256 of the canonical frozen state without an LF, complete identity,
revision 1 and observed issuance BOOTTIME. The separate COMPAT version is bounded
at 4096 bytes. Original checks bracket preparation; any entropy or validation
failure retains and refuses the same authority/storage/fence without retry.

The Heartbeat nonce is SHA256 of the distinct challenge domain, NUL and complete
canonical LF challenge. Existing DiagnosticRequest v1 signatures remain unchanged.
The signature therefore commits to the challenge and its original reservation
bindings, rather than merely a new request id. Randomness is public but generated
only once after acknowledgement; it is not a key or bearer execution credential.

challenge_to_sign exports a read-only byte slice without refreshing or checking
freshness. That data may already be stale. Copies cannot change the held bytes,
regenerate entropy, replace the original issuance point or reconstruct an owner.
collector_challenge_nonce strictly inspects schema/canonical grammar and computes
the digest only. Even all-zero random hex is valid grammar; inspection cannot
attest that a CSPRNG was used. Only the original runtime constructor supplies that
provenance under still-valid admission.

## One response and refusal

accept_response consumes the challenge and one original kernel packet. The same
reservation moves into the existing progress guard, with retained issuance as
its immutable receive-order boundary. That guard remains byte-identical: actual
kernel sender/time, same receiver, original configured controller, request,
identity/revision/source/preset and original live chain are still checked.
After authentication, the same immutable packet must contain the exact challenge
digest as its nonce. A new signed packet for a different commitment refuses.

The challenge expires exclusively ten seconds after original observed issuance.
Both early and final checks sample the same original kernel context and preserve
clock order. The final check follows the original progress checks. Original
60-second holds and all original signed/OIDC windows remain in force. Reads and
revalidation renew neither clock. Failure keeps the original owner, fence and
received packet until drop, latches every retained input and allows no retry or
additional I/O after refusal. A result accepts no replacement packet or state.

This establishes a response bound to a post-ack challenge commitment, not proof
that a controller downloaded or reviewed every Reserved byte, continuous
liveness, a global nonce ledger, recovered acknowledgement or execution authority.
Old generic heartbeat preflight cannot be converted into the causal type.

## Remaining Starting handoff

Starting must still have a separate consuming authority handoff, signed state,
durable replay/uncertain-outcome handling and real SIGKILL/lost-ack boundaries.
The handoff must explicitly define discharged admission predicates and live
configuration/epoch/context/progress obligations rather than refresh old clocks
or stop checking expired inputs in an existing guard. Root outputs, authenticated
original executable/streams/process/cgroup start, watchdog, all-writer cessation
and real host/trust enrollment remain prerequisites for server admission. No
product candidate, expensive workload or qualification is activated here.

The four-fixture live composition runs through a separately registered manual
gate on current and MSRV; pure and API checks remain ordinary. The
[tiering preregistration](diagnostic-collector-causal-tiering-20261016.md) follows
the expanded ordinary group's signed-window refusal. Only an ignore attribute
changes in the composition source, with its original body pinned by SHA256.
The ordinary regression still uses default parallelism and no skipped old tests.
This scheduling boundary is not a runtime fix, a widened authentication window
or proof of arbitrary shared-load robustness. The 900-second manual harness guard
changes no ten-second challenge/progress or 60-second admission budget.

The untiered default-parallel attempt retained 96 passes, four failures and two
existing manual ignores. Three old composition tests and the new live composition
failed through Authentication(Time), including a child-thread failure reported by
its old parent test. No generic kernel refusal site was attributed by that run.
The negative source and transcript remain in the local evidence packet. Tiering
does not establish the complete cause or remove the need to review runtime
validation cost before a future lifecycle authority handoff.

The subsequent tiered default-parallel original-input regression also remains
negative: 98 passes, one Authentication(Time) failure in the unchanged old
heartbeat composition and three manual ignores. No build or whole-workspace
formatting ran alongside it. Separating the new live proof therefore did not
establish a green ordinary regression or solve the original validation-cost /
fixed-window interaction. Keep that blocker explicit; an isolated proof cannot
waive the parallel failure or admit a server launch.

The isolated four-case proof passes on both Rust 1.94.0 and MSRV 1.88.0; each
ordinary focused causal group passes four tests with that one manual case
ignored. Each compiler also passes 29 kernel tests (one existing manual ignore),
30 projection tests and 28 compile-fail examples. Eight Linux/Windows check and
strict-Clippy lanes, 175 static contracts, formatting, documentation, registry
and the local non-promotable contract pass. These focused greens preserve the
explicit ordinary-regression blocker above; they are not a release gate waiver.
