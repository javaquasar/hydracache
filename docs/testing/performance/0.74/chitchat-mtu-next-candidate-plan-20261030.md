## One proposed isolated candidate: borrowed input and existing scratch

Use a new source-only variant derived from U; preserve B/Z/U and every previous
implementation/first result. Limit source work to private serializer/delta
internals. Do not change public `Serializable`/`Deserializable`, wire layout,
MTU, rejection policy, product checks, runtime lifecycle or trust configuration.

Investigate a private visitor for the known serialized DeltaOp/string fields.
It must expose the exact same bytes as the existing public serializer using
borrowed slices and fixed-size scalar headers, without a temporary owned item.
Existing serialization remains the independent byte oracle. This proposal does
not assume that arbitrary external Serializable implementations can be downcast
or borrowed; the public trait must remain untouched.

Only the ambiguous original bound branch uses a transactional fixed-storage
simulation of the existing block compressor. Preserve cheap rejection on the
old bound and cheap acceptance on a correct conservative bound. The test-only
exact predictor must produce max(original estimate, actual predicted finish),
matching the independent safe oracle. No changed supported admission or wire.

Source audit adds a necessary isolated prerequisite: the existing stateless bulk
function creates a compressor/context for each call. The saved changed-budget
counterexample compresses4 times against B's3 and already records two extra C
allocations. Removing a Vec alone does not remove that schedule. First use a
separate control input with a lazily owned per-writer compressor/context, before
combining it with any borrowed-input algorithm. Its native allocation, live/peak,
error reset, context lifetime and retained-memory effects must be measured rather
than assumed. Do not conflate that control's effect with the MTU implementation.
Both steps remain local and must keep every existing threshold; a failed
prerequisite stops this candidate. No new public trait, global context or Vec.

The production operation should consume its successful simulation when appending,
instead of compressing the same blocks twice. Investigate keeping a reusable tail
inside the EXISTING compressed-block scratch, with explicit validity metadata;
do not add another Vec or retain speculative bytes/capacity after rejection.
Every subsequent append/finish must invalidate or consume the exact matching
tail. A changing budget, cheap branch, panic or failed item must preserve the
original pending prefix and all writer capacity contracts. This remains a
hypothesis, not an asserted allocation/CPU improvement.

Derive fixed-storage limits from the complete u16 item/block domain, including
threshold1 and final tags. A naive whole-prefix design can require roughly393KiB
of stack at the worst case; this is a source-derived risk estimate, not an
accepted implementation budget. Establish exact overflow/stack bounds before
coding. No unsafe Vec over stack memory, uninitialized-read shortcut, thread-stack
increase, global arena, heap pre-reservation or omitted input domain is allowed.
If bounded safe storage cannot meet the existing contracts, decline this design
before measurement. Do not replace a heap claim with unmeasured stack/RSS cost.
