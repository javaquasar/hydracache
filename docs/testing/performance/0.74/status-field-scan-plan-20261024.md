# Status field scan baseline and isolated candidate

The native output-preparation profile records 39,744 status projections taking
138,900,023 ns inclusive wall. This is a bounded leaf owner, not the whole kernel
cost or a promise to close the admission budget. The parser currently scans each
fresh status document separately for Pid, Tgid, Uid, Gid and Groups.

First compile the exact baseline struct/function and current group collector in
a dependency-free GNU 1.94 control. Only the Linux ucred data shape and error/trace
plumbing are supplied by the harness; it neither reads proc nor creates an owner.
The baseline source digest must match the retained runtime. Preserve its first
build/check/measurement results. Source extraction boundaries refuse ambiguity.

Afterward implement one invocation-local field index over the same freshly read
bytes. Keep UTF-8 validation, duplicate detection, parse order, 33-token cap,
credential/group predicates, all read/observation counts and original windows.
No retained byte/validation cache, syscall change, start or dispatch is included.
Runtime differential/property tests compare the exact old parser and first
refusal classification, including multiple simultaneous errors and CRLF inputs.

The pure CPU control freezes seed `0x07405ca1`, eight shuffled documents for each
512/2048/8192-byte target shape and 20,000 parses per shape. Generated document
lengths may exceed the target by a final noise line. Baseline/candidate must have
identical workload witnesses, iterations and semantic transcript bytes. Run five
alternating pairs in separate processes once; retain every first result. The
leaf is accepted only if all semantics pass and the upper 95 percent paired
geometric-mean CPU-ratio bound is at most 0.85 for every shape. Do not change the
floor after results. Wall time is retained separately, not the primary estimator.

This leaf gate does not authorize original-owner retries or establish product
throughput, full preparation margin, delivery, writer retirement or release
readiness. Whole-runtime Linux compilation/lint and focused regressions follow
any accepted leaf before a separately admitted full preparation gate.
