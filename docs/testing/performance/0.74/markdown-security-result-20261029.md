# Reviewed pulldown-cmark 0.13.5 security successor

The compatible candidate passes its focused gates and is integrated in the 0.74
working candidate. It does **not** close workspace/security policy or authorize a
server run, merge, publication or release. Chitchat S stays declined.

## Finding and source/effect review

The first Windows whole-workspace milestone refused four findings. The new one,
[RUSTSEC-2026-0414 at the observed DB revision](https://raw.githubusercontent.com/RustSec/advisory-db/40f5be6fb12ed93fc591bf4ab23b7d793b3f2239/crates/pulldown-cmark/RUSTSEC-2026-0414.md),
affects enabled wikilinks and is fixed in 0.13.5. The actual prost-build 0.14.4
cleanup path enables `Options::all() - Options::ENABLE_SMART_PUNCTUATION`, so the
finding cannot be dismissed on the basis of the parser's default options.

Official archives and metadata for both versions were checksum checked. Their
manifests differ only in package version: dependency declarations, feature sets,
MIT license and minimum Rust 1.71.1 remain identical. Root MSRV remains 1.88.
Archive SHA-256:

- 0.13.4: `e9f068eba8e7071c5f9511831b44f32c740d5adf574e990f946ddb53db2f314e`;
- 0.13.5: `278e9268c93b9e498a2da46c34d90ba93a3255eb99009646398f34bc73ab36eb`.

Review covers both changed production files, not only the advisory line.
`parse.rs` repairs wikilink sibling ownership/previous-node tracking and empty
display nodes, bounds malformed ranges before subtraction, records list flags
and propagates underscore search bounds. `firstpass.rs` preserves byte/character
boundaries for definition lists and uses the updated list/paragraph scans.
Nested blank-list scanning changes too. The build-script additions are confined
to existing `gen-tests` generation. Actual locked all-feature root metadata has
683 packages and an empty parser feature set; `gen-tests` and SIMD are absent.
No new active host effect, dependency or public API signature is introduced.

and corpus bytes were fixed before compilation, with separate compiler/variant
targets. Each actual test executable is identified from Cargo JSON, hashed and
listed before running its complete three-case inventory. Registry source members
are compared with official source archives; nonroot GNU uses a separate private
offline vendor directory. Actual compiler version/host and source/HEAD/boot

Both wiki-only and actual consumer parser options are checked for 1/2/4/8/16/32/64
copies. The declared one-million-event cap counts without collecting events, so
the broken baseline does not allocate exponential event buffers. The candidate
matches the predeclared `4*n+1` oracle in all 14 observations per peer. Short
malformed/Unicode inputs are also bounded. The corpus consists of six fixed
plain/list/code/link/table/Unicode examples and both real proto comment blocks;
it is not a whole-Markdown-language equivalence claim.

The snapshot probe enables default HTML/getopts features so it can record HTML.
Root consumers enable neither. SIMD is absent in both configurations; the changed
production parsing paths are not conditional on HTML/getopts. Separate actual
consumer builds below cover the root feature configuration. GNU qualification
here concerns the parser fixture, not a new full GNU workspace qualification.

## Actual consumers and root adoption

Before editing root lock, the two real HC/2 packages were built and tested on
Windows 1.94 and 1.88. Each compiler passed 97 cases / 14 targets, zero ignored,
plus locked/offline all-target/all-feature check and strict Clippy. The candidate
then passed the same complete per-target catalogs and all those checks. Four
generated files, including the protobuf descriptor, are byte-identical. Independent
offline analysis binds them to both actual Cargo `build-script-executed` out_dirs;
it does not infer output identity from an old target-directory glob alone.

lists; that AssertionError remains recorded. Inspection showed equal per-target
cases and generated bytes, with different Cargo completion order. The corrected
offline comparison preserves both raw orders and rejects duplicate/missing targets.
No compiler, product test or parser execution was repeated for that correction.
Eight inert producer/accounting fault controls pass.

Root Cargo.lock changes only pulldown-cmark's version and official checksum;
all 683 package records, dependency edges and manifests otherwise stay exact:
