# Historical source normalization cost

Two separate first Windows debug cohorts measure existing historical source
normalizers without replacing their code. Four nested prefixes produce 72 records;
the existing namespace adapter and its original predecessor chain produce 18
more. Neither cohort is repeated. These observations do not establish the cause
of the retained 780-second package timeout or accept a product optimization.

## Exact scope and inputs

`history_probe.rs` is an opt-in child of `authority_context_074`. The prefix
protocol is committed as `6ade8faaf34ee9bc1091942b9e9fdbcce0c8e3a3`; namespace
integration and additional preservation controls are committed as
`3fc437d3d59419ae9e95bb7e5209675ca01ba9dd`. The three current inputs are pinned to
`d2984650`: authority registry, kernel origin and kernel admission. Each cohort
retains its first runtime-IO preparation spans, prepared-input hashes, compiled
source inventory and executable digest separately from timed prefix work.

Every cell has six records of sixteen calls. Prefix order reverses in alternate
blocks. The second cohort measures only `fixed_slice_namespace_guard::normalize`;
it does not repeat the four earlier operations. Importing its original module
chain and aliasing the same document module avoids duplicate exported macros or
importing the fixed-slice module's existing 432-source test into another target.
There is no replacement implementation, copied normalization body or cached
current-input validation. Diagnostic input strings are prepared explicitly.

The outermost `performance_contract_074_fixed_slice::normalize` is not timed:
its four path predicates have their own earlier allocation evidence. This study
is not every path in the package, an original-owner live run or complete
fixed-slice end-to-end attribution. The nested prefix intervals overlap; the
namespace cohort is a separate process. They cannot be added or subtracted to
derive exclusive per-layer costs.

## First observations

Median wall milliseconds per call on Rust 1.94/MSVC debug:

| Input | Context prefix | Hex prefix | Preparation prefix | Document prefix | Namespace chain |
| --- | ---: | ---: | ---: | ---: | ---: |
| authority registry | 0.068 | 0.131 | 0.282 | 0.298 | 0.291 |
| kernel origin | 0.031 | 0.029 | 0.395 | 0.486 | 0.586 |
| kernel admission | 0.089 | 0.092 | 0.594 | 0.716 | 0.862 |

Six within-process records are not six independent host replications. Coarse
15.625-ms parent-CPU accounting produces zero or quantized deltas; zero does not
mean no CPU. Hashing and consistency checks occur outside timed intervals. No
allocator interposes and no observer time is subtracted. These timings provide
no allocation/RSS/retention evidence or product latency claim.

All eighteen namespace outputs have exactly the independent frozen source
digests from `a33bd9a4d0e910ec71b78f640f19b8404517ce2f`. The new preservation
tests also compare full bytes, retain an injected executable body as a mismatch,
and reject missing/duplicated namespace hooks. Prefix outputs intentionally
represent different historical stages; they are not asserted mutually equal.

The observed per-call costs alone cannot explain the package timeout without
call frequency, path distribution and surrounding work. They also do not justify
weakening syntax admission or caching fresh checks. No normalizer optimization
is installed on the strength of this table. Next attribution should establish
the dominant complete-test/call owner, rather than infer a package win by
multiplying an unrepresentative microbenchmark or shortening the test inventory.
