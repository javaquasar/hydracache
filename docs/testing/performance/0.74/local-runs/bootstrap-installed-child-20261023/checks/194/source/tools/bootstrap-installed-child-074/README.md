# Installed child consistency controls

This local component suite does not install or enroll a bootstrap. The new
`--systemd-bootstrap-installed-v1` mode checks seventeen asserted child slots,
including an ordinary installed inode distinct from the sealed reference. It
always exits 2: matching synthetic material is not original authentication.
Root ancestry, namespace/policy, manager custody and original delivery remain
closed. No new integration target or qualification gate is added.

Run `python -B tools/bootstrap-installed-child-074/check.py host`, then `194`
and `188` for GNU and MSRV WSL component controls, then `metadata`. Host and
metadata both use the Windows Cargo cache; do not run them concurrently. GNU
and MSRV use separate caches. `baseline` is historical and now refuses; every
output lane is exclusive and first failures must be retained. A `-final` lane
is for an explicitly corrected component, not retrying an original live attempt.

The commands contain no original-live, performance, privileged, service, clock
or server action. Private synthetic files and owned subprocesses are cleaned by
test fixtures. The old fifteen-role capture and all original windows stay
unchanged. No FD transport, start/send/exec or release is enabled.

After reviewing checks, commit their exact sources, then run
`python -B tools/bootstrap-installed-child-074/retain.py --checked-commit SHA`.
The retainer refuses failed/incomplete lanes, altered snapshots/commands/logs,
qualification drift, commit drift and packet overwrite. It records synthetic
consistency separately from original authority. A build hash is an unsigned
check artifact, not a trusted build receipt or server admission.
