# Fixed boot/namespace paths and GNU retirement

Local WSL Ubuntu kernel checks only. No server connection, installation,
supervisor operation, product load, original manager send, completion or fence
release occurs. Qualification inputs and all 300/60/10-second origins/deadlines
remain frozen. This packet is not release admission or an end-to-end proof of
the privileged original manager path.

## Baseline before implementation

`baseline-gnu194/` runs the earlier unprofiled GNU image from
`7c523942f0ecba1011a09d63ec1e2531923b7538`, SHA256
`60a114158989e84db95a5a77ecc1b5c37031ed54f5d45d0b784ef9c05733b649`.
All three fresh retirement callbacks and the eight-case frame regression pass.
Thus the local GNU retirement gate already passes before the path candidate;
it would be incorrect to credit a later pass to the optimization. The older
closed negative packet is neither edited nor retrospectively explained.

Retirement controls retain `auth=68`, `channel_checks=4`, zero retry work after
retirement and original bounds. Root kernel controls in these full-frame tests
are simulated. Real root faults and a combined protected original constructor
are different gates. Normal retirement refuses the owner before returning its
borrow; this does not prove confinement or cessation of every writer.

## Negative timing calibration

The original [wall protocol](../../fixed-leaf-path-plan-20261019.md) and its
successive calibration corrections are preregistered. All timing data in this
packet are A/A, before any runtime candidate; no optimized-image wall data
are promoted. Three calibration methods are retained:

- `aa2-*` compares frozen-reference and actual leaf functions in one image.
  GNU boot falsely appears faster: +4.549%, interval [1.134%, 7.968%].
- `aa3-*` uses an opaque caller and balanced ABBA/BAAB. GNU namespace still
  falsely appears faster: +3.375%, interval [1.274%, 5.394%].
- `aa4-*` invokes the actual entry externally in byte-identical images. MSRV
  namespace falsely appears slower: -2.448%, interval [-4.519%, -0.420%].

Intervals use the unchanged seeded 5,000-resample estimator and 45 paired
blocks per leaf/compiler. Each external cohort executes 720 real one-test child
processes; aggregate success is explicitly not a Rust child-test result. See
`aa-analysis.json`, `aa-v2-analysis.json`, `aa-v3-analysis.json` and raw logs.
Neither a positive nor a negative few-percent wall effect is trustworthy from
these controls. No root cause of the calibration failure is proved. No timing
criterion, deadline or release threshold is relaxed.

`aa-gnu194/` and `aa-gnu188/` retain preliminary runner bookkeeping failures:
18 selected origin tests pass, but the runner expected 15 before accounting
for three existing manager-binding tests. They are not measurement cohorts.
`aa4-build-*` and `baseline-v3-images.log` record external calibration identities.
All later protocols retain their own sources, recipes and image hashes.

## Independent allocation endpoint

The separate [allocation protocol](../../fixed-leaf-alloc-plan-20261019.md) was
committed at `13cdf24e` before runtime implementation. Its endpoint is successful
Rust allocation/reallocation requests and requested bytes, not source-derived
malloc estimates, retained memory, CPU time or latency. It does not replace a
failed wall criterion or authorize a product performance claim.

The opt-in test allocator forwards unchanged to `System`, observes only the
capture thread, and is absent from ordinary test and production images. Two
unit tests cover nesting, unwind restoration, thread state, inactive capture,
zeroed allocation, reallocation and exact deallocation. Frozen references are
byte-equivalent old function bodies. Allocation samples execute actual fresh
kernel calls and close their files; no mocked results or cached checks supply
the counts.

`alloc-baseline-gnu194/` and `alloc-baseline-gnu188/` each record three samples
of 1,024 calls per leaf at source `13cdf24e`. In every baseline sample actual
and reference counts agree exactly: boot 5,120 allocations, zero reallocations,
63,488 requested bytes; namespace 1,024 allocations, zero reallocations,
43,008 requested bytes. These are totals, not memory retained simultaneously.

The isolated runtime candidate is `0317f3dc`: four literal C strings replace
boot-child `CString` construction, and four literal namespace paths replace
formatting. Unknown namespace names still format as before. The generic child
function, open flags, filesystem and metadata observations, bounded read,
close/error order, revalidation/sample/context bodies, full frames and effect
brackets remain exact. Source tests normalize only the explicitly registered
substitution and reject missing/duplicate hooks and body drift. The static
contract switch is test evidence bookkeeping, not runtime host authorization.

`alloc-candidate-gnu194/` is an interrupted cache-waiting clippy invocation,
not a measurement or failed runtime gate. Its logs are retained; the fresh
`alloc-candidate-gnu194-retry/` is the selected GNU cohort. MSRV uses
`alloc-candidate-gnu188/`. These labels and recipes are explicit in the analysis.

Both selected compilers reproduce identical reductions in all three samples:

| Fresh leaf call | Rust allocations before → after | Requested bytes before → after |
| --- | ---: | ---: |
| Boot | 5 → 1 | 62 → 36 |
| Namespace | 1 → 0 | 42 → 0 |

Reallocations stay zero in every sample. No measured counter increases, and
the frozen reference retains its exact baseline counts in the candidate image.
`allocation-analysis.json` retains all totals and the independent endpoint
decision. The 36-byte owned boot value remains necessary; this is not a
zero-allocation or cached boot validator. No speed, syscall, CPU, RSS, retained
memory or product-throughput improvement is demonstrated by these counts.

`source-full.log` retains an initial 296/297 source run: a preparation registry
assertion counted all newly appended leaf tests as preparation tests. The
correction routes that assertion through the exact leaf block normalizer;
all previous predicates remain. A source comparison freezes the entire old
test after removing only that adapter, and missing/duplicate registry blocks
are rejected. The final run is separate, never an overwrite of the failure.

The allocation-cost candidate is retained after all its preregistered semantic
and functional checks pass. Ordinary GNU/MSRV images pass 18 origin regressions
each, without the allocation observer. Final GNU image SHA256 is
`f0ed6849c788fd889802bdcb81331110c6ad8874d770606283480b931b67e7dc`;
MSRV is `d37f051b5117c78b52ce1551d405f8a5f9e93b019c3ebe187fee8cacde12a108`.
`candidate-gnu194/` passes three fresh retirement callbacks and all eight frame
scenarios with no retry, original bounds and the same simulated-root scope.
The exact local timesyncd service is restored active. Fixture inventories
before/after contain the same nine unchanged files. Baseline and final gate
success are separate observations, not evidence that the candidate fixed the
historical failure or improved functional-test duration.

The final source suite passes all 297 contracts after the exact test adapter
at `16a66316`; Windows passes 54 units and 18 doc/compile-fail controls. Both
GNU compilers pass strict all-target/all-feature clippy. Formatting, xtask
strict lint, documentation, the 184-gate registry and local non-promotable
performance contracts pass. Prior creator, negative retirement and preparation
packets retain valid original inventories and negative-control verifiers.

Remaining gates are protected host-root admission, combined privileged original
manager/guardian construction and delivery, all-writer confinement/cessation,
durable completion and reconnect. These measurements and simulated controls
do not close those gates or authorize server installation or product workload.

Run `profile.ps1` with a fresh cohort label on GNU 1.94 and MSRV 1.88 for opt-in
counts; run `leaf.ps1 -Stage build` for ordinary images. Neither runner overwrites
cohorts, and both require clean selected source, stable HEAD and exact image
identity. `allocations.py --self-test` checks seven negative controls; its normal
mode verifies baseline equality, reference stability, reductions and no cost
increase. `analyze.py` belongs to the negative timing experiment only.

`frame.ps1` uses an ordinary unprofiled image, nonroot UID1000 and existing
signed fixture files as data, never executed or installed. It stops only the
previously authorized local WSL timesyncd service, settles for 65 seconds,
probes REALTIME separately for 65 seconds, runs three fresh retirement controls
and the old eight-case regression, then restores and verifies the service in
`finally`. It never changes clocks or widens an attempt's original bounds.

The final inventory covers every raw file, including preliminary failures and
negative timing controls. `verify.ps1 -Seal -SelfTest` seals once; subsequent
`verify.ps1 -SelfTest` validates hashes, identities, allocation endpoint,
unprofiled retirement scope, restoration and ten refusal mutations. Do not edit
or reseal this packet after closure. New evidence belongs in a new packet.
