# Authority leaf name ownership control

The [preregistered plan](../../authority-leaf-name-plan-20261020.md) isolates
temporary name cloning in retained journal leaf revalidation, not context parse
or inventory. Frozen owned-open/reference, borrowed-read proposal and actual
arms cover record, commit, early metadata refusal and a synthetic missing
retained name. The last case changes only a test fixture's name assertion;
actual unlink/rename faults are separate ordinary tests because original inode
metadata may refuse before reopening. No production pathname is changed.

Each case has 32 warmups and three rotated 1024-operation samples per arm on
GNU 1.94 and MSRV 1.88. Complete eight-case inspect controls must conserve
record-plus-commit savings at one/seven generations without changing other
leaves, read/write or kernel counts. Captures count successful Rust requests,
not libc calls, CPU, latency or retained memory. Full production ancestry and
the complete ActiveAuthority wrapper remain outside this fixture.

The first new source-canary terminal run refuses an extra blank line after
removing the appended gate. Its exact failing case is reproduced to a retained
log before repair because the terminal output was truncated. The retained
gate snapshot lacks the leading newline present in the appended registry
block. Repair only that new exact template; keep runtime, all old assertions
and the refusal unchanged. This occurs before measurement, not a cohort retry.

Local synthetic nonroot work only: no server/live matrix, installation,
supervisor, clock/service operation, product workload or qualification. All
live checks and 300/60/10 deadlines remain. Separate boot/process identities
cannot prove continuous time or open any independent native/execution gate.
