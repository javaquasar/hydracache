# Original held delivery and child readiness exchange

The next local candidate separates held bootstrap delivery from the historical
two-writer dispatch exchange. The latter remains byte-for-byte unchanged.
No clock, service, namespace, server, product workload or admission deadline is
changed by this work. The qualification manifest remains frozen.

The original installed-entry owner must retain the newly encoded request and
all its descriptor aliases. A separate socket pair carries readiness traffic:
the existing release channel must remain empty under every old full frame.
The new request transfers the seventeen original roles and one readiness role,
addresses the retained unique manager, preserves the original serial and unit
hardening, and uses only the fixed installed bootstrap pathname. It never falls
back to a pathname output or the legacy direct-worker command.

Dispatch and child exchange each latch before their first possible send. Send
failure, manager error, timeout, malformed response and lost acknowledgement
cannot restore permission to send. A manager job reply is not child readiness;
child readiness is not authorization to execute, completion or writer cessation.
The readiness packet binds the installed-entry digest, source context, manager,
client, invocation, original owner, observed child and original absolute bound.
Kernel credentials and an atomically received pidfd, not SO_PEERCRED or packet
PID assertions, identify each sender.

Local checks cover the wire, irreversible transitions, peer substitution,
malformed/duplicate packets, acknowledgement loss and descriptor retention.
Full frames remain before and after the owner-bound operations; no old frame is
removed or replaced by a cached result. The first results are retained separately
from any correction lanes. No performance or original-window-fit claim follows
from component-test timings.

The new eighteen-role child entry, its exact activation environment, actual
manager delivery, original-role proof and all-writer retirement must pass their
own integration gates before execution is admitted. A codec or synthetic
exchange cannot satisfy those gates. Until then the installed child modes remain
refusal-only and no product execution CLI is opened.
