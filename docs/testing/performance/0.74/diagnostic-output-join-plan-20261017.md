Rust 1.94 and 1.88. Run single-flight on the already authorized dedicated host,
in a new private temporary directory, preserving the previous packet. Keep the
installed binary/receipt, boot, supervisor PID/start/restarts and no-active-context
pre/post guards. No root constructor, installation, service operation, clock
change, product workload, Actions or qualification is permitted.

First measure three fresh accepted Starting-to-pipes chains per compiler. Capture
wall time and existing IPC authentication/signature counters separately for
consent preparation, Starting publication, pipe preparation and validation.
Counters cover the named IPC primitives only; signature time is nested inside
authentication and must not be added to it. In three separate fresh chains,
attribute the offered first-round validation checkpoints; explicitly report the
unhooked closing round and final-clock tail as a residual, not as a single leaf.
Do not add diagnostic revalidations inside the publication measurements.
Every error is a retained observation, never retried into acceptance. These are
cost diagnostics, not product throughput evidence or numerical release claims.

## Process-loss gate

Only after joined acceptance, execute all nine Starting effects, six pipe cuts,
ten sink effects and successful-return/lost-ack cuts with owned original pidfds,
bounded barriers, exact partial inventories, Busy-until-drop and fresh read-only
inspectors. Use three repetitions per compiler and retained explicit seeds.
Distinguish process loss from power loss. No inspector may reconstruct an owner,
restart work or publish completion. Stop on an unexpected refusal; preserve the
partial coverage and fix or withdraw that candidate before a new cohort.

Authenticated original-start, pumps/watchdog, writer revocation, completion and
cells 2–4 remain later gates. This work does not open server product admission.

## Candidate J1 schedule, frozen before candidate data

The current-compiler baseline completed all three publication chains and three
separate leaf chains. Starting used 646 IPC authentications in 38 rounds; pipes
used 136 in eight rounds. ReservedLive dominates the offered working round.
Signature counters alone do not explain that cost. Do not change its original
recursive leaf implementation in J1: that would combine two hypotheses.

J1 changes the outer effect schedule, not any leaf predicate. Its consuming
entry begins with the admitted original framed consent and owns the entire
Starting-to-sinks sequence; no intermediate owner can be extracted. At each
effect bracket, run one fresh complete eight-step working round before the
effect and another fresh complete eight-step closing round after its hook.
This deliberately removes the redundant second complete round *on each side*,
not a live predicate or the closing validation. There is no reuse of the
previous effect's postcheck as the next effect's precheck. The old standalone
Starting/pipe publishers and ordinary two-round revalidators remain unchanged.

| Region | J1 full live rounds | Additional object checks |
| --- | --- | --- |
| Starting | 9 fresh before/after pairs plus one before durable acknowledgement: 19 | Same begin/step/ack storage implementations, ordered effects, exact bytes and fsync |
| Pipes | Before the first hook, fresh before each allocation and after each initialization, then after the final hook: 6 | Same pipe2/initialize/inspect primitives, partial inventory, exact flags/identity and final completeness |
| Sinks | Entry round plus 10 fresh before/after pairs: 21 | Same root privilege, retained ancestry, name/digest, exact descriptor/name/inventory checks and fsync effects as the archived candidate |
| Public output revalidation | Original two-round pipe/Starting validator | Complete sinks inspected before and after; no mutable proof cached |

Each round calls the original frame's exact StorageBefore, ReservedLive,
Progress, Causal, Prepared, Consent, StorageAfter and FinalClocks implementations
in order. Thus J1 performs 46 complete rounds in construction, versus the
archived composition's 88; the pipe region adds fresh pre-allocation observations
rather than borrowing its previous postcheck. This is an explicit orchestration
frequency change. It is not a claim that two sequential samples are atomic or
that transient adversarial ABA between observations can be excluded.

The public constructor requires root UID/GID and takes no path, FD, state,
credential, clock or owner assertions. A separate cfg(test) entry runs the same
algorithm with the actual nonroot fixture owner. Failure at any stage retains
the one partially initialized output owner and latches all original inputs.
Descriptors remain private; no process or pump runs. Test hooks occur only
before the unhooked closing observation, never after it. Require exact expected
interruption/refusal variants, all region order/count assertions, late trust and
descriptor mutation controls, and no new deadline-writing assignment before
accepting a new server cohort.
