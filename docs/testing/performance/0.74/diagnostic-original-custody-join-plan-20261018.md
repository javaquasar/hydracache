# Original custody and sink validation join

Baseline 4f5c8a6fd12a1f2bddf9642b4499db60f16ab6b3 has a checked private
Fence custody primitive and a separate fixed-origin grouped preparation owner.
The operator authorizes composing custody with the original sinks and complete
validation frame, without installing a release, stopping the supervisor or
running a product workload.

## Ownership and observation boundary

Add a nonexecuting OriginalCustodiedPreparation that consumes the existing
OriginalGroupedPreparation and retains its same sinks, pipes, unsent message,
bundle, alarm and borrowed original chain. A crate-private storage bridge may
retain only its own original common-fence custody after acknowledged Starting
storage validation. It accepts no caller descriptor, pathname, key or time.
The underlying Fence implementation and default destruction stay unchanged.

Bracket custody acquisition with two unchanged grouped validate calls, each of
which performs the existing full opening and closing original_round. Store the
obtained private custody in the owner before any further fallible operation.
Compare its retained metadata and CLOEXEC flag with the original fence; no
reopen, re-lock or guessed kernel ownership is accepted. Mark the new owner ready
only after the closing full validation and custody inspection succeed. Subsequent
revalidation repeats both full frames and custody inspections, never cached
authority. The expected authentication count is 68 for the new bind and 68 for
its revalidation, in addition to the unchanged preceding preparation.

All old validator bodies, observation calls and the original 300/60/10-second
origins remain exact. No new timer, renewal, public FD export, writer or send/start
path is added. Fixture paths and fault checkpoints exist only under cfg(test).
Failure latches the entire original chain and returns an owner retaining sinks,
message aliases and any acquired custody. Original fields drop before custody,
so closing their writers cannot follow release of that last custody descriptor.

This binds nonexecuting ownership, not exclusive collector sink transfer or an
independent guardian. Authenticated original start, parent alias closure,
complete cgroup revocation, external supervision and successful completion/later
cells remain separate execution gates.

## Declared checks

First run a fresh unchanged grouped baseline control. Add a healthy new-owner
screen, then three fresh controls per compiler checking exact authentication
counts, unchanged time origins, retained records, busy common lock and empty
original sinks. Add persistent refusal cases at opening/retained acquisition and
later revalidation: trust, bundle, output, message, writer, state/projection,
alarm, missing/substituted custody, changed descriptor flags, fixed-origin
refusal and original progress expiry. Refusal must remain sticky without retry
or replacement, holding the original lock until deliberate owner destruction.
No late time refusal can certify detection of an unrelated mutation.

Add compile-fail API checks for execution, cloning, extraction and reuse. Retain
previous runtime/static guards with only exact declared registration/bridge
exceptions and independent mutation negatives. Run both GNU compiler/MSRV
all-target checks, strict all-feature Clippy, formatting, static contracts,
registry, documentation and local non-promotable performance contract.

If the healthy/fault joins pass, use a separately registered nonexecuting process
harness for selected custody acquisition and unacknowledged-return SIGKILL cuts.
Its acknowledgement is test-only, not systemd delivery. Pin owned children before
observation, preserve snapshots and require fresh retained-history refusals.
Use only nonroot isolated temporary fixtures, with dedicated-host pre/post
supervisor/receipt/context guards if exercised there. Preserve negative results;
do not change an original deadline or omit a frame to obtain a positive result.
Commit implementation separately from retained evidence and article conclusions.
