# Dedicated Linux qualification host

The remaining W12 lanes and subsequent Linux qualification runs use the explicitly selected
`hydracache-ax42` SSH host. Windows `cargo xtask verify` remains a separate local check.

The host workspace is `/home/hydracache-admin/hydracache-075-qualification`. It contains the
source repository, private toolsets, an incoming source-bundle directory and `runs/<source SHA>`.
Use strict SSH host-key checking. The separate rental-host alias has an unexpected host key and
is excluded until its identity is resolved.

## Inputs and execution

Rust 1.88.0 and 1.94.0 have LLVM tools, Clippy and rustfmt. Temurin 17 and 21, Maven 3.9.11 and
cargo-deny 0.19.8 are installed into the private toolset. The toolset manifest records exact
download URLs and archive hashes. Tools and dependencies were downloaded directly from their
public upstreams; local Maven caches and local tool archives were not exported.

The D-Bus development package is extracted into a private SDK, using the host's existing
runtime library and daemon. Its pkg-config prefix points into that SDK. No system package
installation, Docker daemon startup or GitHub runner registration is needed for these runs.

Transfer a reviewed source-only Git bundle and verify its prerequisites on the host. Each
qualification uses four clean, independent checkouts of the same committed SHA:

| First wave | Second wave |
| --- | --- |
| Rust 1.88.0 / Java 17 | Rust 1.88.0 / Java 21 |
| Rust 1.94.0 / Java 21 | Rust 1.94.0 / Java 17 |

Run at most two lanes concurrently on the eight logical CPUs. Each lane retains its own target
directory, Maven repository, raw profiles and captures. The existing 43-minute internal build
deadline and 45-minute outer timeout remain unchanged. Failed attempts retain their logs and
exit codes; retries use fresh attempt-specific evidence directories.

After all four lanes succeed, invoke the actual source-built `xtask imap-ci-check` over their
four receipts. Check source SHA, lane identity, workflow hash and the digest of each coverage
report. Retain the execution script, host/toolset manifest, receipts, reports, all attempt logs
and a hashed artifact index. A server run does not become accepted evidence merely because the
remote SSH command exited successfully.
